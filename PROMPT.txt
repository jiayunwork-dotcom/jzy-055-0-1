电子工程师手里常有一张手绘的电路草图，想快速知道稳态下各节点到底是多少伏、某条支路流过多少电流，或者一个 RC 回路充电要多久才逼近电源电压。我们要为这种需求做一个电路求解服务：接收一份网表描述，用修正节点分析法把整张网络组装成线性方程组求解，既能算直流工作点，也能沿时间轴推出瞬态波形。它没有画布也没有拖拽，只以 HTTP 接口对外供数，所有电学计算都在服务端完成并可被独立检验。

先说网表怎么描述。一份网表是一组元件，每个元件有唯一名称、它连接的两个节点名、以及一个参数值。支持的元件包括电阻（欧姆）、电容（法拉）、电感（亨利）、独立电压源（伏特）和独立电流源（安培）；电容和电感允许附带一个初始条件（电容初始电压、电感初始电流），缺省为零。整张网络必须恰好有一个接地参考节点，约定名为 0 或 gnd，其电位钉为零。解析阶段要把下列情况逐一挡回并给出机器可读的错误码与一句人能看懂的说明：出现未知的元件类型、某元件缺少必需的节点、整张网表找不到接地参考、电阻取值为零、两个元件重名、若干理想电压源首尾相接围成一个回路（会让方程组奇异）。解析器遇到这些情况要干净地返回错误，绝不能崩溃，也不能悄悄丢弃某个元件继续算。

直流工作点是核心的第一步。对线性电阻网络，按修正节点分析法组装：电阻在导纳矩阵上贡献自己的电导，独立电流源把电流注入到右端向量，独立电压源则引入一个附加的支路电流未知量、把矩阵扩维，从而同时解出各节点相对地的电位和每个电压源支路的电流。求解线性方程组时，若系数矩阵奇异——比如存在一个不与任何元件相连的悬浮节点、或电压源围成回路——必须判定并报错，而不是返回一堆 NaN 或无穷大。直流工作点下电容视为开路、电感视为短路，但要注意这套元件模型必须和瞬态那套保持一致：电容的初始电压、电感的初始电流在两种分析里含义相同，不允许直流和瞬态各写一份互相打架的元件方程。

瞬态分析沿时间推进。用户额外给一个时间步长 dt 和一个终止时间 tstop。采用隐式的定步长积分（后向欧拉或梯形法二选一，选定后在说明文档里写清并全程只用这一种），每前进一步就把电容、电感用其伴随模型离散成一个等效电导并联一个等效电流源，再解一次修正节点方程，记录这一时刻各节点电压，如此逐步得到一条时间序列。要挡回的非法情形包括：dt 不为正、tstop 小于一个 dt、以及总步数超过一个明确设定的上限（例如两万步）以防失控。有几条物理上必然成立的关系要由自动化测试逐条守住，而不是靠肉眼看波形像不像：一段电阻分压网络的直流解，各节点电位之比要和手算的分压比在数值误差内吻合；一个 RC 串联充电电路从零初值出发，瞬态末端的电容电压要按指数规律逼近电源电压，且逼近到某一比例所需的时间要与该回路的时间常数（电阻乘电容）相符；把电容的初始电压设为某个非零值，瞬态第一个时间点算出的状态要与这个初值自洽衔接、不能突跳。

对外提供两个计算接口：一个接收网表、返回直流工作点（各节点电位、各电压源支路电流、是否求解成功）；另一个接收网表连同 dt 与 tstop、返回一条时间序列（每个时刻的时间值与各节点电压，足以在别处画出一条曲线）。凡是网表非法、矩阵奇异、或参数越界，都以带错误码和说明文字的错误响应回复。请随服务内置两个可手工核对的算例：一个是电阻串联分压网络，直流解能笔算验证；一个是 RC 充电回路，瞬态末态电压逼近电源电压、时间常数与元件值一致。

实现上请用 Python 3.12 搭配 FastAPI 承载这套服务，线性代数可借助 NumPy。请把职责拆分到多个模块与文件里：网表的解析与合法性校验独立成一块，修正节点分析的矩阵组装与线性求解独立成一块，瞬态的时间步进与元件伴随模型独立成一块，HTTP 接口层只做请求转发与结果封装，不要把解析、组装、步进的逻辑塞进同一个巨型文件。交付物要能通过一个 Dockerfile 构建成镜像、容器启动后接口即可访问，运行时固定为 Python 3.12；同时附带一套自动化测试，覆盖分压比与手算一致、RC 末态与时间常数吻合、电容初值自洽、以及上面列举的各类非法网表都被正确挡回。
